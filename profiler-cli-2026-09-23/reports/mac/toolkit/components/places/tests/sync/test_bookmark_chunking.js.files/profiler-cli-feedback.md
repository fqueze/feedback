- Command: `profiler-cli thread samples --include-idle --session test_bookmark_chunking.js-1` (per-test xpcshell profile of task ORElD1phRy6Tawee5eXRPw, 621 samples).
  Expected: the same 621 samples, now with idle ones counted. Got: `Categories (0 running samples) — No samples in the current view.` and empty function lists. Without the flag, 621 running samples are shown. Workaround: none; left idle out.
- Command: `profiler-cli thread samples --session test_bookmark_chunking.js-1` on the full range. The Categories block counts 621 running samples, but "Top Functions (by self time)" lists 3 functions at 1 sample (33.3%) each, and "Heaviest stack (1.0 samples)". Zoomed to 12.342,16.322 the self-time list is sane (81 samples). Workaround: zoom first.
- Question: "what was machine CPU during this test's window, in the resource-usage profile?". Command: `profiler-cli zoom push 1156.19,1192.74` then `thread markers --search "name:CPU Use" --list --limit 0`. The list shows one row per 100 ms `CPU Use` marker with no field values, so reading CPU% needs `marker info` per row. Workaround: `--json` and a Python summary (min/median/mean of `data.cpuPercent`). What the output could have shown: a summary of the marker's numeric fields over the view, e.g. "CPU Percent: min 100.0%, median 100.0%, mean 100.0% (367 markers)".
- Question: "exact start and end of this `test` marker in the resource-usage profile" (to zoom the job timeline to it). `marker info m-1` prints `Time: 19m16s - 19m53s (36.547s)`: minute:second rounding on a 32-minute profile loses the sub-second start. Workaround: `marker info m-1 --json` for `start`/`end` in ms.
- Question: "how much CPU did the whole xpcshell process get, next to its main thread?". `profiler-cli counter info c-0` (Process CPU) prints 22–36% per bucket while `thread info` gives the main thread alone 28% over the same range, so the counter's unit (one core, or all cores) is not said. Workaround: none; left the counter out of the report. What the output could have shown: the unit and its normalization, e.g. "% of one core".
- Question: "how many cores does this machine have?". `profiler-cli profile meta` on a per-test xpcshell profile prints no CPU name or core count, and `--json` has none either. Workaround: cited nothing.

## From the review (review-test_bookmark_chunking.js)

- Question: "which tests were running at t=1157 s, with their status?" (resource-usage profile). Command: `profiler-cli thread markers --search 'name:test' --list --limit 0`. `name:` is a substring match, so `TEST-PASS`, `xpcshell-test` and every `test_*` payload match as well. Adding `-name:TEST` to exclude the `TEST-*` markers excluded everything, because the exclusion is case-insensitive and also hits `test`. Workaround: `--json`, then filter to `name == "test"` and to intervals containing t in Python. What the output could have shown: an exact-name match (e.g. `name:=test`), and a filter for markers whose interval contains a time or overlaps a marker (e.g. `--at 1157` / `--overlapping m-1`).
- Question: "is the machine at 100% CPU only around this test, or for the whole parallel phase?". Same gap as the `CPU Use` summary entry above, but over time: `--json` over about 19,000 `CPU Use` markers, bucketed per minute in Python. What the output could have shown: per-bucket stats of one numeric field, e.g. `--field-stats cpuPercent --buckets 60s`, the way `counter info` already prints "over time".
