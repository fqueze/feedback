## Question: "did each timed-out test actually run for its duration, or end right after it started?"
- Commands: `profiler-cli thread markers --search name:test --list --limit 0` and `--search "will retry" --list --limit 0` on a resource-usage profile, then a Python script. The script paired each TIMEOUT `test` marker with its "<test> failed or timed out, will retry." INFO marker and computed the gap (median 22 ms, i.e. the launch failed instantly).
- What the output could have shown: a per-status summary of `test` markers with their start-time range (e.g. "PASS: starts 13.1–49.1s; TIMEOUT: starts 39.3–55.8s"). That would have shown the mass start of 1149 tests in 3.6s with 20 threads, without a script. `--group-by field:status` gives counts and durations, but no start range.
