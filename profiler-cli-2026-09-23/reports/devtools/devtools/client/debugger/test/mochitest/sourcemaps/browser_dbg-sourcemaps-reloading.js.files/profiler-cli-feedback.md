
## review-browser_dbg-sourcemaps-reloading.js (2026-09-22)

- `profiler-cli marker info m-180` (a Network marker). Expected: the payload's `startTime`/`endTime` and phase timestamps on the same timeline as the marker's `Time` and every other marker. Got: under "Fields (raw payload, no schema)", `startTime: 91288.4107` and `endTime: 91555.7882`, while the marker itself spans 91281.79-91549.17. That is 6.6 ms off, the same as `profile meta`'s "Uptime: 6.619ms". The original report quoted the raw values as if they were on the timeline. With `endTime` that would put the load's end after the error it caused. Workaround: take `start`/`end` from `marker info --json` and ignore the payload times. Suggestion: shift the payload timestamps like the marker's own, or label them as unadjusted.
- `profiler-cli --session X thread markers ...`: `error: unknown option '--session' (Did you mean --version?)`. `--session` is accepted only after the subcommand. Expected: accepted as a global option too, or a hint saying where it goes.
- `profile-link.py --session <id> --marker m-N` refuses a session loaded from a `profiler.firefox.com/from-url/...` link ("A link needs the raw artifact URL"). `review-brief.md` says to check links by `profiler-cli load <link>`, so a reviewer who wants to add a link has to load the profile a second time (0.6 GB) from the raw Taskcluster URL. Suggestion: have profile-link.py pull the artifact URL out of a from-url link.
