## `Issues (first failure per run)` counts TEST-KNOWN-FAIL messages as the failure, splitting one failure into two
- Command: `fx-tests test browser/components/tabbrowser/test/browser/tabs/browser_tab_groups_tabContextMenu.js`
- Expected: one issue, `group2 menu item has correct label - null == "Unnamed group"`, 109x.
- Got: issue 2 (that message, 58x, all Windows) and issue 3 `handleEvent() was unable to perform a11y checks on hidden node: id: context_moveTabToNewGroup ...` (51x, all macOS). In the profiles that a11y message is `TEST-KNOWN-FAIL` (a11y-checks todo), on both platforms. On macOS the native context menu makes it fire in an earlier subtest than the real failure, so it wins "first failure"; on Windows it fires after. `fx-tests task --messages` also lists the known-fail messages (`Clicked menuitem ... which was not open`, `changed preference: ...`, the a11y ones) next to the real failure with no status.
- Workaround: `fx-tests task <id> --messages` for all 97 jobs, dropping the known-fail kinds by text: every job has the group2 label message. Took 97 calls; showing the status (FAIL vs KNOWN-FAIL) per message, and skipping KNOWN-FAIL when picking the first failure, would have answered it directly.
